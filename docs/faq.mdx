# Frequently asked questions

## Where do I connect?

For an Ethereum-compatible app or wallet, use NEVM mainnet (chain ID **57**), Tanenbaum NEVM testnet (**5700**), or zkSYS Genesis testnet (**57057**). For native SYS UTXO payments, use Syscoin Core on the corresponding network. [NEVM endpoints](./reference/nevm.mdx) · [Genesis endpoint](./reference/zksys.mdx#public-genesis-testnet) · [Core ports and network flags](./reference/core.mdx)

## What is the difference between PoDA and storing data forever?

Syscoin Core checks the full blob when it validates a fresh publication. The block commits to the blob's digest. A node syncing old history can validate the commitment after Core's payload requirement expires. If your application needs the data later, keep an archive and check recovered bytes against the digest. [Publication, retention, and replay](./architecture/data-availability.mdx#retention-and-replay)

## Which post-quantum features are deployed?

Syscoin Core mainnet uses BLS ChainLocks. The proposed post-quantum rules use SLH-DSA for Sentry Node identity and WOTS+ for finality votes. zkSYS also has an experimental hash-based smart-account signing module. Refer to the status page for deployment details.
