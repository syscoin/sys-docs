# Frequently asked questions

## Where do I connect?

For Ethereum-compatible apps, NEVM mainnet uses chain ID **57**, Tanenbaum NEVM uses **5700**, and the zkSYS Genesis testnet uses **57057**. For UTXO payments, connect to a Syscoin Core node on the matching network. [NEVM endpoints](./reference/nevm.mdx) · [Genesis endpoint](./reference/zksys.mdx#public-genesis-testnet) · [Core ports and network flags](./reference/core.mdx)

## What is the difference between PoDA and storing data forever?

A hash lets a reader authenticate bytes they can retrieve. Core requires payloads when validating fresh publications. A node syncing historical blocks can accept older commitments after the payload requirement expires. An application that needs to replay those batches later must obtain the bytes from a source that kept them. [Publication, retention, and replay](./architecture/data-availability.mdx#retention-and-replay)

## Which post-quantum features are deployed?

Released Core mainnet uses BLS ChainLocks. The PQ release candidate authenticates Sentries with SLH-DSA and verifies their scheduled WOTS+ votes directly. zkSYS has a separate experimental hash-based signing module for smart accounts.
