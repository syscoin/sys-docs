# Z-DAG Developer Guide

Use Z-DAG to check an unconfirmed Syscoin Platform Token (SPT) transfer before it is mined. The result reflects the transaction and its unconfirmed ancestors in your node’s mempool. [Z-DAG design and whitepaper](../../tech/z-dag.mdx)

The eligible format is allocation send, transaction version `142`. The queried transaction and each unconfirmed ancestor must meet the 1,100-byte size limit. If a fee input comes from an unconfirmed native SYS transfer, the SPT transfer can be ineligible. [Size policy](https://github.com/syscoin/syscoin/blob/v5.1.3/src/policy/policy.h) · [Mempool ancestor checks](https://github.com/syscoin/syscoin/blob/v5.1.3/src/services/rpc/assetrpc.cpp#L26-L70)

## Understanding Z-DAG Statuses

`assetallocationverifyzdag "<txid>"` returns a numeric `status` based on the node's mempool checks.

| Status | Description |
| :----: | :---------- |
| `-1` | The transaction was not found by the mempool check. It may already be confirmed. |
| `0` | Z-DAG OK. The node's checks passed. |
| `1` | The transaction or an unconfirmed ancestor signals replace-by-fee (RBF). |
| `2` | The transaction or an unconfirmed ancestor is not a Z-DAG transaction. |
| `3` | The transaction or an unconfirmed ancestor exceeds the Z-DAG size limit. |
| `4` | The node detected a double-spend conflict involving the transaction or an unconfirmed ancestor. |

Core v5.1.3 returns the codes above. An update under development adds status `5` when the node exhausts its capacity for recording input conflicts. The warning replaces an otherwise passing result until restart. [Core v5.1.3 status enum](https://github.com/syscoin/syscoin/blob/v5.1.3/src/primitives/transaction.h#L79-L88) · [Updated status checks](https://github.com/syscoin/syscoin/blob/b3b4f643383a2149807a25fe38d26b5f058daa60/src/services/rpc/assetrpc.cpp#L27-L110)

After your Z-DAG waiting period, **only numeric `0` means the local checks passed**. For every other result or RPC error, verify the payment on the active chain and wait for the required confirmations.

## Using Z-DAG Balances

Core 4.x exposed a `zdag_balance` through `assetallocationbalance`. Core 5.0 removed that RPC. In Core 5.x, apply the transaction status and confirmation checks above to each transfer. [Core 5.0 release notes](https://github.com/syscoin/syscoin/blob/v5.0.0/doc/release-notes/release-notes-5.0.0.md#9-removal-of-deprecated-syscoin-4x-asset-rpcs)
