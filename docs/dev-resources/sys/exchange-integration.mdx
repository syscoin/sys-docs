# Syscoin UTXO integration

Specify the network, asset, amount, and settlement policy for every deposit and withdrawal path. SYS on Core and SYS on NEVM use different transaction models and monitoring interfaces.

| Task | Core interface |
| --- | --- |
| Verify network and sync | `getblockchaininfo`, `getnetworkinfo` |
| Read an active block | `getblockhash`, `getblockheader`, `getblock` |
| Decode an available transaction | `getrawtransaction`, `decoderawtransaction`, or indexed [Blockbook transaction lookup](/docs/dev-resources/documentation/javascript-sdk-ref/blockbook#get-transaction) |
| Check UTXO status | `gettxout` |
| Inspect unconfirmed Z-DAG status | `assetallocationverifyzdag` |

Follow the active chain on reorgs and verify that a transaction pays the expected output before crediting it. A non-wallet transaction may need `-txindex` or its block hash for raw transaction lookup. Run `syscoin-cli help <method>` against your deployment for parameter details.

If your policy uses unconfirmed payments, [Z-DAG](/docs/dev-resources/sys/z-dag) explains the local status signal and the confirmation fallback. For NEVM receipts and logs, use the [NEVM JSON-RPC reference](/docs/reference/nevm).
