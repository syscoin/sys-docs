## Cryptography and proofs

- **Stateless hash-based signatures.** FIPS 205 defines SLH-DSA from SPHINCS+ and standardizes SHA-2 and SHAKE parameter sets. The candidate Core identity profile, `SLH-DSA-SHAKE-128s`, has a 32-byte public key and a 7,856-byte signature. Scheduled WOTS+ is a separate Syscoin protocol with a one-time-use signing rule. [NIST FIPS 205](https://csrc.nist.gov/pubs/fips/205/final) · [Syscoin's ChainLock design](../architecture/post-quantum.mdx)
- **Limited-signature smart accounts.** The zkSYS precompile uses the separate `SLH-DSA-SHA2-128-24` profile from the NIST SP 800-230 initial public draft. That profile limits each signing key to 2²⁴ signatures. The account or signer must enforce its key-use limit because a stateless verifier cannot count signatures. [NIST SP 800-230 draft](https://csrc.nist.gov/pubs/sp/800/230/ipd) · [Pinned verification and conformance notes](https://github.com/syscoin/zksync-os-server/blob/v0.24.4/contracts/README.md#slh-dsa-sha2-128-24-verifier-status)
- **Module-lattice signatures.** FIPS 204 defines ML-DSA. For a wire-size example, ML-DSA-44 uses a 1,312-byte public key and a 2,420-byte signature. Public-key size, signature size, signing policy, and cryptographic assumptions all matter when deciding what to deploy. [NIST FIPS 204](https://csrc.nist.gov/pubs/fips/204/final)
- **Hash functions.** RFC 7693 defines BLAKE2s, FIPS 202 defines SHAKE and SHA-3, and FIPS 180-4 defines SHA-256. Core PoDA accepts both BLAKE2s and legacy Ethereum Keccak-256. Exact algorithm, encoding, and domain matter when comparing or recomputing digests. [RFC 7693](https://www.rfc-editor.org/rfc/rfc7693) · [NIST FIPS 202](https://doi.org/10.6028/NIST.FIPS.202) · [NIST FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final) · [PoDA encoding](../architecture/data-availability.mdx#what-the-hash-commits-to)
- **Hash-based proof systems.** The FRI paper introduces a Reed–Solomon proximity test. A deployed proof system builds on components like this and adds its own transcript, commitment, recursion, and verifier choices. Check the active verifier before carrying a security claim through a wrapper or bridge. [FRI paper](https://doi.org/10.4230/LIPIcs.ICALP.2018.14) · [zkSYS proving path](../architecture/zksys.mdx)
- **Bitcoin interoperability research.** This design paper explores a verification-based Bitcoin bridge using BitVM concepts. Bridge contracts and custody paths need independent evidence of deployment and verification. [Bitcoin bridge research paper](https://syscoin.org/btc_bridge.pdf) · [Syscoin whitepapers](https://syscoin.org/research-whitepapers)

## Design essays by Jagdeep Sidhu

These essays trace the project's design choices over time. Their economic parameters, performance examples, and deployment descriptions reflect the period in which each was written. [Author archive](https://jsidhu.medium.com/)

- **August 2025 · Decentralized intelligence.** As autonomous systems gain the ability to use shared resources, the essay asks who sets the rules and how others can audit decisions. Its Earth–Mars example explores local accounting, exclusive reservation of assets, and proofs that another ledger can verify after the message arrives. [Truth States, Consciousness, and Decentralized Intelligence](https://jsidhu.medium.com/truth-states-consciousness-and-decentralized-intelligence-d5415da47dc6)
- **March 2024 · Bitcoin modularity.** Examines the security obligations of bridging, DA, and execution separately. It uses Rollux as a historical case study and explores trust-minimized BTC interoperability proposals. [Rollux — Creating a new layer 0 for Bitcoin modularity](https://jsidhu.medium.com/rollux-creating-a-new-layer-0-for-bitcoin-modularity-e2d737c99168)
- **June 2022 · Turing, AI, and a coordinated computer.** Uses the Von Neumann model to explain how common ordering, a data layer, and independent execution can form a shared computing system. The final section connects Turing and von Neumann's work on machine intelligence with the need for open access to compute and coordination among autonomous agents. Its interplanetary example is an early argument for local execution and delayed settlement. [Blockchain as a coordinated global Von Neumann architecture](https://jsidhu.medium.com/blockchain-as-a-coordinated-global-von-neumann-architecture-2876e3c7b0ea)
- **April 2022 · The base-layer design.** A republished public thread covers why Syscoin pairs a UTXO chain and an EVM and uses a finality mechanism alongside merge mining. [Why Syscoin is the ideal layer 1](https://jsidhu.medium.com/why-syscoin-is-the-ideal-layer-1-3ff690a7ef5f)
- **January 2022 · Independent checks and PoDA.** Describes the motivation for full-node verification, merge mining, proof of service, modular execution, and a separate data path. This is an early statement of the PoDA design. [Blockchain Idealisms](https://jsidhu.medium.com/blockchain-idealisms-b61c5781ddc3)
- **December 2021 · Rollup fundamentals.** Explains the difference between validity proofs and fraud challenges, and why both approaches must account for access to the data underlying state updates. [The Ultimate Guide to Rollups](https://jsidhu.medium.com/the-ultimate-guide-to-rollups-f8c075571770)
- **February 2021 · Coordinated financial computing.** Lays out a four-layer model in which a shared history coordinates specialized execution and settlement. [A Design for an Efficient Coordinated Financial Computing Platform](https://jsidhu.medium.com/a-design-for-an-efficient-coordinated-financial-computing-platform-ab27e8a825a0)

## Institutions, computation, and shared resources

- **Machine intelligence.** Alan Turing's 1950 paper frames machine intelligence through the imitation game and examines objections to machine thinking. It provides the historical context for Sidhu's later question about the institutions that coordinate powerful machine actors. [Computing Machinery and Intelligence](https://doi.org/10.1093/mind/LIX.236.433) · [Turing's typescript, King's College archive](https://turingarchive.kings.cam.ac.uk/computing-machinery-and-intelligence)
- **Common-pool resources.** Elinor Ostrom compared successful and failed forms of self-governance of shared resources. Her prize lecture describes recurring features of durable arrangements, including clear membership and resource boundaries, participation by affected users, accountable monitoring, and local dispute resolution. Her later diagnostic work asks how rules should fit the actual participants, incentives, and resource. A cryptographic ledger can make parts of such a process auditable. Eligibility, dispute resolution, and the accuracy of physical measurements still depend on the institutions that supply and govern them. [Governing the Commons, Cambridge University Press excerpt](https://assets.cambridge.org/97811075/69782/excerpt/9781107569782_excerpt.pdf) · [Ostrom's 2009 prize lecture](https://www.nobelprize.org/uploads/2018/06/ostrom_lecture.pdf) · [A diagnostic approach for going beyond panaceas](https://pmc.ncbi.nlm.nih.gov/articles/PMC2000497/)
